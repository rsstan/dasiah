## 2. Nearest stops of a cell (transit-data, `rebuild_hex_stop_access`)

K-nearest-neighbour search on `stops_geom_gix` (GiST, `<->` ordering) limited by `ST_DWithin`.

```sql
SELECT n.stop_id, n.dist_m FROM transit.hex_cells h
CROSS JOIN LATERAL (SELECT s.stop_id, ST_Distance(s.geom, h.centroid) AS dist_m FROM transit.stops s
  WHERE s.feed_version_id = $1 AND ST_DWithin(s.geom, h.centroid, 1500)
  ORDER BY s.geom <-> h.centroid LIMIT 5) n
WHERE h.h3_index = $2;
```

## 3. Timetable export for one date (transit-data internal API)

Services of the date from `service_dates_date_idx`, their trips through `trips_service_idx`,
stop times by the primary key `(feed_version_id, trip_id, stop_sequence)`.

```sql
SELECT t.route_id, t.trip_id, st.stop_sequence, st.stop_id, st.arrival_s, st.departure_s
FROM transit.service_dates sd
JOIN transit.trips t ON t.feed_version_id = sd.feed_version_id AND t.service_id = sd.service_id
JOIN transit.stop_times st ON st.feed_version_id = t.feed_version_id AND st.trip_id = t.trip_id
WHERE sd.feed_version_id = $1 AND sd.service_date = $2
ORDER BY t.route_id, t.trip_id, st.stop_sequence;
```

**Sequential scan on `stop_times`: reviewed, no index added.** One weekday selects 60 % of the
trips of a feed, so the query needs 240 000 of the 400 000 stop times of that feed. They are spread
over every page of the feed, so an index path reads the same pages in key order with more
overhead; 3b forces it for comparison. The export runs once per (feed version, date) and is
cached on disk (`docs/05-algorithms.md#4-timetable-artifact-transit-data---accessibility`), and the
scan grows with the number of stored feed versions, so archived versions should be deleted
(`ON DELETE CASCADE` from `feed_versions`) rather than kept. The sort spills to disk with the
default `work_mem` of 4 MB; the export transaction sets `SET LOCAL work_mem = '64MB'`.

## 6. Outbox poll (every service with an outbox)

The partial index `outbox_unpublished_idx` holds only pending rows, so the poll stays cheap
however many events were already sent. `SKIP LOCKED` lets several publishers run.

WHERE published_at IS NULL ORDER BY occurred_at LIMIT 100 FOR UPDATE SKIP LOCKED;
